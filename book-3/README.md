# Data Agents on Apache Iceberg — companion

This directory implements the examples for the 18-chapter book. The local test
suite (`make test`, 43 tests on real local Iceberg tables), the MCP protocol probe
and the failure drills pass on macOS with Python 3.13.5; the finance and north
receipts return 39,000 and 21,000 cents and the `outsider` principal is refused.
**No model evaluation, catalog-policy test or Spark workflow has been executed yet**;
those need the Book 2 platform and an approved model.

The existing `book-1` and `book-2` environments are unchanged. This book has its
own virtual environment so its MCP and Agent SDK dependencies do not replace
the other books' packages. Python 3.13 is the target; desktop Spark also needs
JDK 21. Direct requirements are pinned in `pyproject.toml`; they are target
versions, not a frozen, resolved installation. Record `pip freeze` after the
desktop install succeeds.

## First bounded query

Run these commands from `book-3/`:

```bash
make setup
make seed
make example
.venv/bin/book3 query --principal north_analyst --metric net_revenue
```

`seed` creates a real local Iceberg V2 table through PyIceberg's SQLite catalog.
It refuses an existing table. `work/` contains the catalog, data, receipts and
operational ledgers. To begin an independent exercise, use a fresh work directory:

```bash
.venv/bin/book3 --work work/second seed
.venv/bin/book3 --work work/second query --principal finance
```

The eight authored input rows are in `fixture.py`. Paid orders contribute gross
less discount less refund. The hand-computed assertions are 39,000 USD cents
for finance, 21,000 for north, and 18,000 for south. Cancelled and pending orders
do not contribute. The query returns integer cents, a snapshot id, table UUID,
schema id, query/parameters and hashes of the semantic model, policy and result.
Snapshot ids and UUIDs are generated by the actual catalog; the book does not
prescribe their values.

This first example exercises application policy over a trusted service identity.
It does not demonstrate catalog-enforced row isolation. `north_analyst` is chosen
by the trusted launcher. A model tool has no argument that can choose its identity.
For a deployed gateway, bind that context to verified authentication and use
separately scoped engine/catalog/storage credentials. A process owner who can
edit the policy or read the service credential is outside the local trust model.

## MCP and the reference agent

```bash
make setup-agent
BOOK3_PRINCIPAL=finance BOOK3_WORK="$PWD/work" make server
```

The server speaks stdio. Do not type into its protocol stream as if it were an
interactive shell. A client starts it and sends MCP requests. It exposes
discovery, definitions, approved metrics, a restricted SELECT tool, metadata
health and maintenance proposals. There is no shell, file-read, staging,
approval or publication tool.

The reference runner uses the author's selected Claude Agent SDK. Authenticate
with Claude Code on the desktop, or configure the SDK's API-key mode through
the environment. Confirm the applicable authentication behavior before the first
paid run. Choose the model explicitly; the runner records requested and observed
model identities rather than printing a guessed model pin.

```bash
export BOOK3_MODEL='your-approved-model-id'
.venv/bin/python -m iceberg_agents.agent \
  --principal finance \
  'What is net revenue in USD cents from 2026-09-01 inclusive to 2026-10-01 exclusive?'
```

The launcher disables built-in tools, uses only its explicit MCP configuration,
ignores project/user setting sources, limits turns and reported dollar budget,
and imposes a wall-clock timeout. The MCP process has its own call budget. These
are distinct controls. A row limit does not limit bytes scanned, and DuckDB's
memory setting does not bound the Arrow materialization preceding the query.
The source-row budget is deliberately small for this teaching implementation.
Production isolation needs an authenticated service boundary and resource limits
around the whole worker, not only the SQL connection.

An answer envelope includes `run_id`. Receiving it and recording delivery are
separate actions:

```bash
.venv/bin/book3 acknowledge ACTUAL_RUN_ID
.venv/bin/book3 export-traces work/runs.jsonl
.venv/bin/book3 ingest-traces work/runs.jsonl
```

The receiving evaluator acknowledges only after it receives the complete
envelope. The runner does not declare its own stdout delivered. Trace-lake
ingestion is a single-writer upsert keyed by run id; no multi-writer exactly-once
guarantee is claimed. Prompt text and raw SDK transcripts are not exported into
the analytical trace table.

## Retaining and replaying an answer

```bash
.venv/bin/book3 retain work/receipts/ACTUAL_REQUEST_ID.json
.venv/bin/book3 replay work/receipts/ACTUAL_REQUEST_ID.json --principal finance
```

Retention creates an evidence tag with a finite maximum age. It consumes retained
storage; it is not a backup or permission grant. Replay checks the current policy,
semantic-model version and table UUID before querying the retained snapshot.
The comparison is the result multiset. It makes no promise of identical new model
wording. Protect receipt storage and define an owner/expiry policy for tags before
using this pattern with sensitive data.

## Desktop REST and Spark profile

Start the shared platform once from `book-2/`; do not run its `down` or `clean`
targets while another exercise uses it. Give Docker about 10 CPUs and 32 GiB
while Spark runs on the host; the platform has failed to start under far less. Measure actual use;
run timing experiments without unrelated engines competing for the same CPUs.

Provide configuration through your shell or a secret manager. No credential file
is committed, and no admin-key fallback exists in the query worker:

```bash
export BOOK3_CATALOG=rest
export BOOK3_REST_URI='http://localhost:8281/api/catalog'
export BOOK3_WAREHOUSE='the-configured-polaris-catalog'
export BOOK3_SCOPE='PRINCIPAL_ROLE:ALL'
export BOOK3_S3_ENDPOINT='http://localhost:8333'
export BOOK3_TABLE='agents_desktop.orders'
# Set BOOK3_CREDENTIAL to the scoped principal's client-id:secret privately.
make setup-spark
```

The book's lab creates fresh `agents_*` fixtures. Give its setup operator only
the necessary sandbox grants. The reader and publisher must not be the same
credential in a deployed system. Polaris namespace/table grants and vended
credentials are exercised by the stack probes with separate allowed/denied
principals; the local policy dictionary is not evidence for those layers.

Only the trusted operator CLI exposes the staged correction:

```bash
.venv/bin/book3 propose --proposer writer --order-id 41001 --refund-cents 100
.venv/bin/book3 stage ACTUAL_CHANGE_ID
.venv/bin/book3 validate ACTUAL_CHANGE_ID
.venv/bin/book3 approve ACTUAL_CHANGE_ID --reviewer reviewer
.venv/bin/book3 publish ACTUAL_CHANGE_ID
```

The candidate is an explicit branch. Validation compares the complete small
fixture, not just counts. Approval binds table identity, base/candidate snapshots,
the requested correction and the validator report. Publication checks that binding and commits with atomic catalog requirements on
the table UUID, main snapshot and candidate branch snapshot. It publishes the exact
approved candidate and reconciles a retry after a lost response. The SQLite ledger assumes
trusted local operators; its reviewer string is not a cryptographic identity.
Protecting the publisher credential and authenticating the reviewer are separate
deployment work. The desktop probe must test main movement, candidate movement,
bad corrections, retry and main visibility before this workflow is certified.

## Retrieval and operating helpers

`Index.sync` consumes a complete key inventory at one captured V3 snapshot.
Row lineage chooses changed content; an anti-join against the complete inventory
finds deletions. Documents and checkpoint commit together. This reconstructs the
current index, not every intermediate source event. The token-hash embedding is
a deterministic fixture for observing index mechanics; learned embedding quality
needs its own model, version and evaluation.

`health.observe`, `operations.assess` and `operations.plan` keep observed counters,
diagnostic thresholds and proposed actions separate. The planner cannot execute
maintenance. `incident_packet` requires timestamped observations and links every
hypothesis to evidence and a next check. `evaluation.release_decision` counts
failed attempts and missing delivery and refuses unscored releases.

## Complete desktop route

[DESKTOP.md](DESKTOP.md) gives the ordered public commands, identity controls and
resource boundaries. The public probes are available without the private lab.
`search-current` refuses a stale retrieval checkpoint; retrieval is not exposed
as a model tool in this draft. A numeric answer requires an approved metric
receipt, not a SQL column with a convincing alias. Its free-text explanation
still needs semantic review.

The analytical evaluation keeps failed and undelivered attempts in the denominator
and requires an independent case manifest, three repeats and per-case acceptance.
Unknown provider cost stays unknown. Health, maintenance and incident suites need
human semantic scoring even after their JSON schemas pass. The planner review
ledger records a decision but never authorizes maintenance execution.
